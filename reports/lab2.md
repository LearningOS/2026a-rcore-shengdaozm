# 简答

1. 请列举 SV39 页表页表项的组成，描述其中的标志位有何作用？

答：SV39 一个页表项 64 位，真正有用的低 54 位：上面 44 位是物理页号 PPN，下面 10 位是标志位。标志位（对照我们代码里的 PTEFlags）就是 V/R/W/X/U/G/A/D。V 表示这页映射生不生效；R/W/X 管能不能读、写、执行；U 表示用户态能不能访问这块；G 是全局页标记；A 是访问位、D 是脏位，留给页面淘汰/换出时用，看这页到底被没被读过、改过。

2. 缺页
缺页指的是进程访问页面时页面不在页表中或在页表中无效的现象，此时MMU将会返回一个中断，告知 os 进程内存访问出了问题。
os 选择填补页表并重新执行异常指令或者杀死进程。

2.1 请问哪些异常可能是缺页导致的？

答：取指、读、写三类访问都可能缺页。对应的异常就是 Instruction page fault（取指）、Load page fault（读）、Store/AMO page fault（写）。说白了就是 MMU 发现 PTE 要么不存在、要么权限不够，直接抛异常。

2.2 发生缺页时，描述相关重要寄存器的值，上次实验描述过的可以简略。

答：scause 存异常号，比如 12/13/15 就是上面那三种缺页；stval 存出错的虚拟地址（就是 bad addr）；sepc 存出错的指令地址；satp 还是指着当前这张页表。

2.3 缺页有两个常见的原因，其一是 Lazy 策略，也就是直到内存页面被访问才实际进行页表操作。 比如，一个程序被执行时，进程的代码段理论上需要从磁盘加载到内存。但是 os 并不会马上这样做， 而是会保存 .text 段在磁盘的位置信息，在这些代码第一次被执行时才完成从磁盘的加载操作。
这样做有哪些好处？

答：省内存、启动快、不干无意义活。具体说：① 申请了但不用的页根本不占物理内存，内存紧张时这点最香；② 程序启动不用把整个段都从磁盘搬进内存，用到哪加载哪，启动飞快；③ 像题目说的 10G 只用 1M，eager 做法白建一堆页表还白占物理页，lazy 就只给真正访问的页干活。

2.4 其实，我们的 mmap 也可以采取 Lazy 策略，比如：一个用户进程先后申请了 10G 的内存空间， 然后用了其中 1M 就直接退出了。按照现在的做法，我们显然亏大了，进行了很多没有意义的页表操作。
处理 10G 连续的内存页面，对应的 SV39 页表大致占用多少内存 (估算数量级即可)？

答：数量级约 20MB。算一下：10G/4KB ≈ 260 万个页，每个叶子 PTE 8 字节 → 约 20MB；SV39 是三级页表，高两级（L1 根、L2 中间）对连续 10G 只需几十 KB，可忽略。所以光页表本身就 ~20MB，物理内存还得另算 10G。eager 做法这 20MB 加 10G 全白给，lazy 只给用到的 1M 建表就几乎免费。

2.5 请简单思考如何才能实现 Lazy 策略，缺页时又如何处理？描述合理即可，不需要考虑实现。

答：mmap 时不真分配物理页、不建映射，只在内存里记一笔“这片虚拟地址归我、属性是 prot、还没落实”。访问时 MMU 发现 PTE 不存在或无效 → 抛缺页异常。异常处理里查这地址是不是之前登记的、权限对不对：对就现场分配物理页、填好 PTE、sfence.vma 刷新 TLB、回到出错的指令重跑；不对（野指针/越权）就直接杀进程。核心就是“登记 + 访问时按需落实”。

2.6 缺页的另一个常见原因是swap策略，也就是内存页面可能被换到磁盘上了，导致对应页面失效。此时页面失效如何表现在页表项(PTE)上？

答：被换出后这页的 PTE 把 V 位清 0（无效），MMU 一看到 V=0 就抛 page fault，os 据此知道“这页在磁盘上不在内存”。PPN 那段通常被复用成磁盘上的位置/索引（标记它在哪块 swap 区、哪个槽位），A/D 位清掉。os 接管后去磁盘把页读回物理内存，再把真正 PPN 填回去、置 V=1，重跑指令就行。

3. 双页表与单页表

3.1 为了防范侧信道攻击，我们的 os 使用了双页表。但是传统的设计一直是单页表的，也就是说， 用户线程和对应的内核线程共用同一张页表，只不过内核对应的地址只允许在内核态访问。 (备注：这里的单/双的说法仅为自创的通俗说法，并无这个名词概念，详情见 KPTI )

在单页表情况下，如何更换页表？

答：切换进程时，把新进程根页表的物理地址写进 satp 寄存器，再 sfence.vma 刷掉 TLB 就完事。因为用户和内核都在同一张表里，换页表就是换 satp 这一个寄存器，没有第二套要管。

3.2 单页表情况下，如何控制用户态无法访问内核页面？（tips:看看上一题最后一问）

答：靠 PTE 的 U 标志位。内核页建映射时不打 U 位（PTEFlags 里 U=0），用户态（特权级 U）访问时 MMU 检查到 U=0 直接拒了、抛异常。所以一张表里靠 U 位把内核页和用户页隔开，用户态碰不到内核页。

3.3 单页表有何优势？（回答合理即可）

答：① 简单，只维护一套页表；② 用户态↔内核态来回不用换页表、不用刷 TLB，系统调用和中断处理快得多（双页表每次进出内核都得换 satp+刷 TLB，开销大）；③ 内核想直接读写用户地址也方便，同一张表直接 translate 就行。代价就是没隔离、怕侧信道，所以才搞双页表。

3.4 双页表实现下，何时需要更换页表？假设你写一个单页表操作系统，你会选择何时更换页表（回答合理即可）？ 

答：双页表下，每次特权级跨越都得换——进内核换内核页表、回用户态换回用户页表（系统调用、中断的进出都要换 + 刷 TLB）。单页表的话我只在切进程时换 satp，同一个进程内部用户态↔内核态一律不换，反正都在一张表里、靠 U 位隔开了，省掉每次进出内核的 TLB 刷新开销，性能更好。
